# 交付前自檢

四輪核實抓到的錯誤型態，依類別列。每條後面是當時的實例，看得出是哪種錯。交付前逐條問「這份文件有沒有這個」。

## 歸因與語氣

- 自己新增的設計寫成會議決議。例：「月會後 3 個工作日入庫」逐字稿沒有，只有「有公告就要放進去」。修：標「新增建議，待核定」並附原文時間碼。
- 沒有來源的句子混進事實。例：Wi-Fi 卡加了「拿不到請洽行政中心」。修：只寫有時間碼的內容。
- 保證式語氣。例：「回滾約 5 分鐘」「單張下架即時」「誤觸發風險歸零」「欄位無害」。修：改成「未實測」或「由某測試證明」，測試只能代表已測案例。
- 「負責人皆 X、期限皆本週」一概而論。修：照原始待辦表逐項寫，沒提就寫未提及。
- 測試單、健康檢查回應被當成全流程打通的證據。修：降為推測，列出還缺哪一段證據。
- 「uid 末四碼」寫成匿名化。修：明寫「非匿名化，內容仍可識別個人」，並給不接受時的替代方案。
- 核實意見「成立」被讀成「已解決」。修：處置表加狀態欄，涉及資料表、索引、依賴、回滾者寫「文件已改，待實測」。

## 時間

- 星期心算錯（9/12 其實是週六），整份時程跟著錯。修：`date -d 2026-09-12 +%A` 逐日核，並指出來源紀錄若也錯。
- 「本週」剩幾天沒算。修：把上線拆成能在本週完成的最小一波與下週一波。
- 星期算對了，時程表仍把週六週日排成實作日（skill 測試第一輪抓到）。修：時程每列標星期，週末列寫「不排工作」。
- 每月統計用「週報歸月」。修：以每筆紀錄的時間戳歸月並去重。

## 範圍與依賴

- 「檔案互不重疊」但實際共用檔（週報檔、schema、CI 設定、文件）。修：逐檔指定唯一寫入者；共用檔由一方寫、另一方把內容寫在報告裡。
- 備援 session 加開後沒有重新分配檔案。
- 一個工作包依賴另一個尚未合併的東西（例：清單腳本要讀還沒建立的表）。修：明寫缺席時的處理與測試自建依賴。
- 拍板項「不同意其他不受影響」忽略依賴。修：不同意的項目及其依賴一起暫停。
- 「兩個完成狀態」混成一個（骨架完成 vs 內容入庫完成）。修：拆開，各自驗收。
- 決策沒有可執行的工作包（D9 只有描述、沒有分支與檔案）。修：獨立成包或明寫不做。
- 拍板單缺「只核准查核、不批准修改」選項。

## 驗收與證據

- 驗收條件互相矛盾（要求草稿卡不部署，又要求 smoke 測試命中它）。修：兩態測試，各自有執行者。
- 隔離、過濾類的要求只在流程層，沒有程式層與測試。修：程式排除＋測試證明＋人工複驗，三者缺一不可，並列為上線阻擋項。
- 查詢欄位格式沒證實就寫查詢語法（`cited_notes like '%待確認%'`，該欄根本不存狀態）。修：先確認格式，再設計查法，缺歷史資料記無法驗證。
- 檔案修改時間當版本證據。修：用雜湊對 git blob。
- 快照相鄰兩份相同就當期間沒變。修：只給上下界。
- 備份時點與部署時點之間有空窗。修：覆蓋前對目標檔案現行雜湊核對。
- 密鑰掃描以長度或關鍵字直接判定。修：長度只篩不判，逐筆看內容與用途。
- 回滾只證明「舊程式跑新 schema 不崩」。修：另證明退版後不會重新暴露被隔離的東西，並先做隔離再退版。
- `grep -l` 不遞迴、抓不到不同寫法。修：用解析 frontmatter 的工具，掃描範圍與索引器一致。
- 只 `enable` timer 卻對沒有 `[Install]` 段的 service 也下 `enable`，報錯被誤判部署失敗。

## 規格與派工單一致

- 第三段規格改了，第四段可複製的派工單還是舊規格（配對規則、截斷長度、允許檔案清單、base SHA、資料表欄位名 `狀態` vs `status`）。修：每次改規格就 grep 派工單；交付前用舊句子零命中證明。
- 計數不同步（「12 條」「13 條」「7 件」散在標題、驗收、信號）。修：改完全文 grep 數字。
- 歷史處置表裡被撤回的規則沒標「已撤回」，讀者以為仍有效。

## 資料與隱私

- 個資目錄（員工手冊、聯絡人）被複製到報告或 zip。修：只寫檔名，不複製內容；zip 前 grep。
- 把對話內容寄到第三方信箱沒有標成需要決策的資料流向項。
- 密鑰檔、`.env`、資料庫在任何 session 的禁止清單裡。

## 派工

- 用記憶裡的 session id 派工，全部 not found。修：先 `list_sessions`。
- 決策者只批一小塊，卻照原時程啟動全部工作包。修：範圍縮到那一塊，其餘待拍板。
- 決策者只批一小塊，P0 卻照完整三張單派（建基線、審查準備），等於越權（skill 測試第一輪抓到）。修：只派與那一塊相關的唯讀核實，其他 session 收待命通知。
- 證據檔裡已寫明「改設定即可、不必改程式」，規劃時卻當成未決問題丟給下游（測試兩組都犯）。修：先挑出不用改程式就能做的。
- 「派 P0」被寫成「拍板後才派」或「純唯讀」。修：P0 分層授權明寫，本機建置與跑測試不是純唯讀。
- 通知待命的 session 沒說明範圍，它們沿用昨天的任務。修：待命通知附範圍與禁止事項。
